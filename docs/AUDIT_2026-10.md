## A. Shader `trace()` — geodesics

**A1. Cartesian null geodesic d²x/dλ² = −(3/2) r_s h² x/r⁵, h = |x × v|.** Correct, exact [der].
With h = L, this is the Binet equation u'' + u = (3/2) r_s u² rewritten with λ affine; the first integral
|v|² − r_s h²/r³ = E² reproduces (dr/dλ)² + (L²/r²)(1 − r_s/r) = E². Sanity check: my exact Hamiltonian integrator
(Schwarzschild, J = 0) and a re-implementation of the code's RK4 scheme agree in the hit point to < 1e-5° [der].

**A2. Camera direction rescaling v = v_r r̂ + v_⊥/√(1 − r_s/r_c).** Correct [der]. For a static observer at r_c
and E = 1: p^r̂ = n_r/N, p^φ̂ = n_⊥/N, and ṙ = N p^r̂ = n_r, ρφ̇ = p^φ̂ = n_⊥/N. The inverse at the surface
(`surfPoint`: k ∝ v_r r̂ + v_⊥ N) is also correct.

**A3. dt/dλ = 1/(1 − r_s/r).** Correct for E = 1 [der]. The code integrates it with the midpoint radius `rm`.
The Shapiro-off branch (dtf = mean |v|, i.e. t = Euclidean coordinate length of the bent path) is a consistent
convention; its `Tref = r_c − R_eq` is the matching Euclidean reference, and with Shapiro on
`Tref = Δr + r_s ln[(r_c − r_s)/(R − r_s)]` is the exact radial coordinate light time (same log term as X-PSI
`rays.pyx` l.242 `DeltaLagCor`) [code][der].

**A4. Escape test `h² > rEsc²` and `escapeDir`.** The weak-field remainder **Δ = (r_s/b)(1 − x̂·v̂) is wrong for
the quantity the code propagates** [der]. It is the first-order remainder of the *physical* transverse
force (a_⊥ = −r_s b/r³, integrated from the current point to infinity it gives (r_s/b)(1 − cos φ₁), with
cos φ₁ = x̂·v̂). But the code's `v` is the coordinate velocity dx/dλ of the affine Cartesian formulation,
whose transverse acceleration is a_⊥ = −(3/2) r_s b³/r⁵, concentrated near closest approach. Integrating that
from a point with x̂·v̂ = c to infinity gives the exact first-order remainder

```
Δ_coord = (r_s / 2b) (1 − c)² (2 + c)         (→ 2 r_s/b for c = −1, r_s/b for c = 0, ≈ 0 for c → 1)
```

Numerically (exact Schwarzschild integration to r → ∞) [der]:

|---|---|---|---|
| b = 15.4 km, leaving r = 4R outward (c = 0.95) | 0.063° | **0.75°** | 0.0004° |
| b = 20.5 km, same | 0.15° | **0.95°** | 0.002° |
| b = 30.8 km, same | 0.56° | **1.19°** | 0.013° |
| b = 46 km, same | — | 0.72° | 0.15° |
| b = 51 km from the camera (the `h² > rEsc²` shortcut) | 10.7° total | **1.95°** | 1.30° (2nd-order remainder) |
| b = 84 km from the camera | 4.7° total | 0.60° | 0.25° |

So the whole lensed background (star arcs, studio grid) is over-deflected by 0.75–1.2° wherever the ray has
passed the star, which is every background pixel within ~2.5 R of the limb. The tooltip's "up to ~0.7° off right
next to the limb" understates it and gets the trend backwards (the error grows away from the limb to 1.2°). The
surface image is unaffected (surface hits never use `escapeDir`). Fix: use Δ_coord above; for the camera shortcut
also consider lowering the threshold or adding the (15π/16)(r_s/b)² second-order term.

**A5. Frame dragging as rotZ(x, v) by −ω dt per step.** Sign of the *drift* correct, **but rotating `v` is wrong**
[der]. In the slow-rotation metric ds² = −N²dt² + dr²/N² + r²dθ² + ρ²(dφ − ω dt)², ω = 2J/r³, the geodesic has
φ̇ = ω ṫ + L_z/ρ² (the drift the code reproduces with the right sign: a backward-traced photon in a prograde-dragged
spacetime must rotate by −ω dt) and ṫ = (E − ω L_z)/N² with p_r driven by the ω′L_z term. The latter is the
gravitomagnetic deflection: prograde photons are bent *less*, retrograde *more*, by ∓4J/b² in the weak field
(Sereno & De Luca 2006; Iyer & Hansen; "deflection enhanced for retrograde and reduced for prograde photons") [snip].
Rotating `v` rigidly by ∫ω dt = 4J/b² instead applies the *same-sense* kick to every ray. Test in flat space + ω(r),
b = 15 km, J = 1.595 km² [der]: exact deflection −1.53° (prograde, away from the star) / +1.73° (retrograde);
code scheme +1.62° for *both* (toward the star for the prograde ray). The code therefore gets the differential
Lense–Thirring deflection with the wrong sign, and only reproduces the uniform image twist (which for a varying
ω(r) is the correct physics only for the L_z = 0 rays).

The true dragging effect at the limb (3–4°) is 5× the "~0.6° twist" the tooltip quotes. The redshift `g` at the
code's hit agrees with the exact `g` to 0.01% (716 Hz) and 0.1% (0.5c), so the colour/brightness error is only
through the position shift. The code also omits the ω L_z/N² term in dt/dλ: arrival-time asymmetry up to 1.5 km
(5 µs, 1.3° of phase) for grazing rays at 716 Hz. Severity: the frame-dragging step is advertised as an
approximation and the effect is small over most of the disc, but what is shown is not an approximation of the
right thing near the limb. A correct first-order scheme: keep the position drift, do *not* rotate `v`, and
propagate the Schwarzschild part with the local effective energy E − ω(r)L_z (or integrate the Hamiltonian above).

## B. `surfPoint()` — local frames, normal, g, emission time

**B1. Static-frame photon direction k.** Correct [der] (see A2).

**B2. Oblate normal.** Correct [code][der]. The gradient of r − R_eq(1 + o₂ z²/r²) is coded correctly, and dividing
the tangential part by √(1 − r_s/r) gives tan γ = (R′/R)/√(1 − r_s/R) = Morsink et al. 2007 Eq. 3 as implemented
in X-PSI `mesh_tools.pyx` `f_theta` l.90–93 (`radiusDerivNormed / (radius * sqrt(1 − 2ζ/radius))`), with
cos γ = 1/√(1 + f²) [snip]. Max tilt 8.3° at the fiducial star. (Note the lapse is keyed to the bending bit, not the
redshift bit, a decomposition choice.)

**B3. β_Ω = Ωρ/N, β_Z = (Ω − ω)ρ/N, g = N√(1 − β_Z²)/(1 − β_Ω k·e_φ).** **Exactly right to O(ω²)** [der], with the
caveat on what k·e_φ is. Derivation: emitter u^μ = u^t(1, 0, 0, Ω), u^t = 1/√(N² − ρ²(Ω − ω)²) = 1/(N√(1 − β_Z²));
photon p_t = −E, p_φ = L_z; E_em = −p·u = u^t(E − ΩL_z), so g = N√(1 − β_Z²)/(1 − Ωℓ), ℓ = L_z/E
(the Cunningham–Bardeen form) [der]. The code's k is built from the Schwarzschild-part velocity, whose φ component
is L_z/ρ with E = 1, so k·e_φ = N L_z/(ρE) ≡ c₀ and β_Ω c₀ = Ωℓ exactly. c₀ is *neither* the true static-frame
cosine (cos ξ_s = c₀ + β_ω) *nor* the ZAMO cosine (cos ξ_Z = c₀/(1 − β_ω c₀)); it is the quantity that makes the
coded formula exact. Had k been computed in the real ZAMO frame the exact form would be
g = N√(1 − β_Z²)(1 + β_ω cos ξ_Z)/(1 − β_Z cos ξ_Z) (differs by β_Ωβ_ω k²: 0.5–0.8% in g at 716 Hz, 2–6% at 0.5c).
Numerical check with the exact slow-rotation geodesic and exact −p·u: code g agrees to ≤0.01% (716 Hz) and
≤0.14% (0.5c) [der]. The frame-dragging change of g is a near-uniform +0.4–0.6% at 716 Hz (g⁴: +2%), as the
project notes say. The same δ = E_static/E_em is also the right aberration factor (B4/C). Static-frame speed
β = ΩR sinθ/(c√(1 − r_s/R)) matches X-PSI `integrator.pyx` l.301 [code].

**B4. `te = uT − (T − Tref)` and the Shapiro-off branch.** Correct and self-consistent [der]; the constant offset
Tref only fixes the phase origin, and `projectPoint` uses the same convention for the field lines.

## C. Aberration and limb darkening

cos α′ = δ cos α with δ = 1/(γ(1 − β cos ξ)): correct [code][der]. X-PSI `integrator.pyx` l.388–397: `eta =
Lorentz/(1 + beta*cos_xi)` (opposite sign convention for ξ), `_ABB = mu * eta`, `_Z = eta * Grav_z`; μ there is
the static-frame cosine to the *tilted* normal (l.351–358), as here (`cosA = dot(k, n)`). Proof: the normal has no
φ component, so p′^n = p^n and cos α′ = p^n/E′ = (E_s/E′) cos α. The code's `delta` is E_static/E_em including
dragging (B3). `limb(μ) = (1 + 2.06μ)/3.06`: the standard approximation to Chandrasekhar's H-function for an
electron-scattering atmosphere ("I(μ) ≈ 1 + 2.06μ", Suleimanov et al. 2012 arXiv:1208.1467, crediting
Chandrasekhar/Sobolev) [snip]; the 1/3.06 normalises I(1) = 1, so "yellow = 1 = face-on, no relativity" holds.
It is applied with the comoving μ = δ cos α (`s.mu`): correct. Attribution to Poutanen & Gierliński 2003 is
unverified [mem]. (NICER fits use NSX hydrogen atmospheres, more strongly limb-darkened [snip].)

## D. Beaming and the blackbody LUT

I_ν/ν³ invariant ⇒ I_ν^obs(ν) = g³ B_{ν/g}(T) = B_ν(gT) exactly, so "a blackbody at T is seen as a blackbody at
gT" with *no* extra factor, and bolometrically ∫B(gT) = g⁴ σT⁴/π [der]. The LUT is not normalised per temperature
(every entry is divided by the same Y_REF = Y(6000 K); `intoGamut` preserves Y), so `bb(gT)` is the correct
observed spectrum and `bb(T·g)` in `shadeThermal` is right [der]. Caveat: the LUT luminance is the *photopic*
(380–780 nm) luminance, whose local index d ln Y/d ln T is 5.2 at the 5000 K display temperature (7.8 at 3250 K,
2.8 at 10 000 K) [der], so the displayed thermal brightness scales as g^5.2, not g⁴. That is correct for "what a
visible-light eye would see of the ×1/400 star" (and the help text only claims "g³ per frequency"), but it is not
bolometric; only the caps/curve use g⁴. The `!F(m,4)` branch (colour of gT, luminance of T) is a non-physical
decomposition used to isolate the "beaming" chip; acceptable as a UI convention, not as physics.

Wireframe: W = g⁴ then (g⁴)^0.4 for display, true g⁴ for caps: as documented, correct.

## E. Hot-cap flux pass

F = Σ I_obs dΩ with I_obs = sp · limb(μ′) · g⁴ and dΩ = dx dy (1 + x² + y²)^−3/2: correct [der]. The pixel solid
angle of a pinhole camera in tan-plane coordinates is exactly that. By Liouville I_bol^obs = g⁴ I_bol^em, and
∫I dΩ over the image plane equals X-PSI's ∫ I′ cos α′ (d cos α/d cos ψ) γ dS′/D² form (X-PSI `_GEOM = mu |dcosα/dcosψ|
Grav_z η³/(1 + β cos ξ)` = μ |dcosα/dcosψ| √(1−u) γ δ⁴, `integrator.pyx` l.398) [code][der]; the image-plane form
needs *only* g⁴ per pixel, which is what the code does. It is bolometric (stated in the tooltip). Two caveats:
(i) the observer is at 85 km (g includes N(R)/N(r_c)), so the pulsed fraction is for that camera, not for infinity;
(ii) the flux-pass FOV sin A = 1.5 R/r_c is smaller than the lensed apparent radius sin a = (R/N_R) N_c/r_c when
N_R < N_c/1.5, i.e. R ≲ 3.4 GM/c² [der]: apparent/FOV = 0.80 (fiducial), 0.90 (J0740), 1.00 (2.4 M☉, 12 km),
1.08 (2.2 M☉, 10 km), 1.12 (2.4 M☉, 10.5 km). The outer rim of the image is clipped from the brightness curve in the
most compact (but still allowed, above the 2.9 GM/c² warning) corner of the sliders.

## F. `phys()`

- **o₂ = Ω̄²(−0.788 + 1.030 x), R(θ) = R_eq(1 + o₂ cos²θ).** Correct [code]: X-PSI `mesh_tools.pyx` l.52 and bender
  `strig.jl` `Rgmf` l.20–22 (o20 = −0.788, o21 = 1.030), both citing AlGendy & Morsink 2014 Eq. 20/Table 1.
  o₂ < 0 for x < 0.765 (pole flattened). Code's x = r_s/(2R) = GM/(R_eq c²) and Ω̄² = Ω²R_eq³/GM match Morsink+07
  Eqs. 9/10 as quoted in X-PSI docstrings [code]. Validity: fitted to models below mass shedding; X-PSI applies it
  for all Ω̄ and adds priors R_pole ≥ 1.505 r_s and −3o₂ ≤ 1 [code]; stated accuracy ≈1% in radius [mem]. The
  clamp `fO = min(f, fK)` freezes Ω̄² at 0.347 (o₂ = −0.21) for the fiducial R_eq, well below the shedding shape.
- **f_K = 1080 √(M/M☉)(10 km/R)^1.5 Hz.** Haensel, Zdunik, Bejger & Lattimer 2009: C_NS = 1.08 kHz, valid for
  0.5 M☉ < M < 0.9 M_max, with **R the circumferential radius of the non-rotating star**; R_eq at the Kepler
  configuration ≈ 1.44 R_static [snip]. The code inserts R_eq. Error [der]: with R_eq = 12 km at 716 Hz the static

  R_eq = 12 km is 1650 Hz; mass shedding corresponds to Ω̄ ≈ 1 [mem]. Verdict: approximation, label "≈" and
  "for the non-rotating radius".
- **I = 0.237 MR²(1 + 4.2 M/R + 90 (M/R)⁴), M in M☉, R in km.** Correct [snip]: Lattimer & Schutz 2005 give
  (0.237 ± 0.008) MR²[1 + 4.2 M km/(M☉ R) + 90 (M km/(M☉ R))⁴] ≡ 0.237 MR²(1 + 2.84β + 18.9β⁴), for EOSs supporting
  ≥ 1.6 M☉ (one 2024 review misprints 1.42). X-PSI instead uses the AGM14 fit √x(1.136 − 2.53x + 5.6x²)

- **J = κ (r_s/2) R² Ω_km [km²], ω = 2J/r³, χ = J/(r_s/2)².** Correct [der]: GJ/c³ = κ(GM/c²)R²(Ω/c), so the
  geometric J is κ(r_s/2)R²Ω_km and ω = 2GJ/(c²r³) → 2J/r³ per km; χ = cJ/(GM²) = (GJ/c³)/(GM/c²)². χ = 0.373,
  ω(R)/Ω = 0.123 at the fiducial star.

## G. Field model

- **Retarded dipole B = [3n(n·m) − m]/r³ + [3n(n·ṁ) − ṁ]/r² + [n(n·m̈) − m̈]/r at t − r.** Correct [der]. From
  Jackson 9.18 (E of an electric dipole, e^{ikr−iωt}): k²(n×p)×n/r ↔ [n(n·p̈) − p̈]/(c²r) and −ik[3n(n·p) − p]/r² ↔
  [3n(n·ṗ) − ṗ]/(cr²); duality p → m gives the magnetic case. Griffiths' far field E = −(μ₀p₀ω²/4π)(sinθ/r)cos(…) θ̂
  equals (1/c²r)[n(n·p̈) − p̈] in Gaussian form, confirming the sign (the alternative m̈ − n(n·m̈) is wrong).
  Numerical check: `fieldAt` vs ∇×∇×(m(t−r)/r) by finite differences agrees to 4e-11 at r/R_LC = 0.7, 2.3, 3.6; the
  flipped-sign version is off by 20–116% [der]. ṁ = Ω ẑ×m, m̈ = Ω ẑ×ṁ with m retarded: correct.
- **Schwarzschild dipole Ψ = sin²θ F(r), F = (3/r) Σ_{k≥3}(r_s/r)^{k−3}/k.** Correct [der][snip]: with ε = 2M/r,
  ln(1−ε) + ε + ε²/2 = −Σ_{k≥3} ε^k/k, so −(3r²/8M³)[ln(1−2M/r) + 2M/r + 2M²/r²] = (3/r)Σ(r_s/r)^{k−3}/k → 1/r;
  closed form matches the A_φ quoted from Wasserman & Shapiro 1983 in arXiv:2608.03320 and astro-ph/0004407 [snip].
  Series and closed form agree to 1e-7 numerically; F·r = 1.359 at the surface [der].
  **Components:** B^r̂ = ∂_θΨ/(r² sinθ) = 2cosθ F/r² ✓; B^θ̂ = −N ∂_rΨ/(r sinθ) = −N sinθ F′/r. The code omits the
  lapse N in B_θ. This does **not** change the field-line shape (lines are contours of Ψ; dr/dθ = −2 cosθ F/(sinθ F′)
  either way) [der], but it matters for magnitudes (see J) and the vacuum-dipole radiation terms are flat-space
  while the static term is Schwarzschild (mixed, O(r_s/r) inconsistency near the star; schematic).

## H. `traceForceFree()`

- sin²θ_pc = R/R_LC: last closed dipole line r = R_LC sin²θ ⇒ correct (aligned-rotator estimate; CKF/Gruzinov find
  the open flux 1.2–1.4× larger [mem]).
- cos θ∞ = 1 − sin²θ₀/sin²θ_pc: correct [der]. Dipole flux through a cap of half-angle θ₀ is 2πμ sin²θ₀/R ∝ sin²θ₀;
  split-monopole flux ∝ (1 − cos θ∞); equating fractions of the open flux (θ∞ = 90° at the cap edge) gives it.
- dφ/dr = −Ω/c beyond R_LC for Ω ∥ +z: correct [der], from B_φ/B_r = −Ωρ/c (Michel) and ρ dφ/dr = B_φ/B_r: a
  trailing spiral. `wind(r)` has slope −Ω beyond R_LC with a C¹ ramp from 0.5 R_LC; the sheet uses the same
  `wind(r)` (`sheetPt`): consistent, as it should be.
- Current sheet n·m(t − r/c) = 0 as the great circle ⟂ the retarded m: correct for the split monopole
  (Bogovalov 1999; cosθ cosχ ± sinθ sinχ cos(φ − Ωt + Ωr/c) = 0 in reviews arXiv:1807.08528, 1608.04895) [snip].
  Phase convention: exact retardation would be rotZ(m, −Ωr/c); the code's `wind(r)` is −Ω(r − 0.75 R_LC) beyond
  R_LC, i.e. a constant +0.75 rad offset. Since corotation inside R_LC (not retardation) is the force-free reality
  and the true asymptotic phase comes only from simulations, this is a schematic choice, not an error.

## I. `beamRays()`

Same integrator and step rule as `trace()`: yes (verified by reading; the surface hit uses the spherical R, not the
oblate surface — a 0.1 R inconsistency at the pole when oblateness is on, display only). Fog weight 1/N when
redshift is on: **half right** [der]. A static observer measures per-photon energy E/N *and* an arrival rate
boosted by 1/N (dτ = N dt), so the locally measured energy flux of a conserved photon stream ∝ density/N²; what the
*camera* would see of light scattered by static scatterers is ∝ density × N²/N² ≈ density (the two blueshifts
cancel against the redshift back out). The intended statement "path density × blueshift" is therefore neither the
local flux nor the camera's view; size: N = 0.81 at the surface, so factors 1.23 (code) vs 1.52 (local) vs 1.0
(seen). Display only.

- GR factor F(r)·r: correct at the pole only. Exact |B|_GR/|B|_flat at the fiducial surface: 1.359 (pole), 1.389

## L. Other items

- **`projectPoint` retarded fixed-point iteration (3 passes).** Contraction factor |dT/dte| ≤ Ωρ|ê_φ·∇T| ≈ ρ/R_LC.
  Converges inside R_LC but slowly near it, and **does not converge beyond R_LC** (the pattern points move
  superluminally). Euclidean-T test, camera 85 km, i = 62°, 716 Hz [der]: azimuth error of the displayed point
  0.4° at ρ = 0.6 R_LC, 2.9° at 0.9 R_LC, 3.7° at 0.97 and 1.5 R_LC, ~100° at 2.5 R_LC. So with "Light-travel time"
  on, the outer closed loops are a few degrees off and the current sheet / open lines beyond ~1.5 R_LC are
  essentially unretarded noise. The correct approach is Eulerian: evaluate the pattern at each *spatial* point with
  its own t_e(x) = t_obs − T(x), which needs no iteration (the surface shader already does exactly this).
- **Beam wavefronts and the `fixed` flag.** Beam vertices are placed at their lab position without light-travel
  delay (single iteration) and the band phase uses the ray's own `aT`, i.e. "where the photons are now", while the
  surface shows "what you see". Internally consistent for the beam, inconsistent with the retard chip; the beam
  clock origin (plane at t = 0) is unrelated to the surface clock (Tref offset): display only.
- **Grid-line hue `spec(490/δ)`.** Uses Doppler only; the observed wavelength is λ/g with g = δ√(1 − r_s/R)/N_c.
  Documented in the help text as a Doppler-only encoding, so a convention; but it means the "gravitational redshift"
  step changes the thermal colours and not the wireframe hue.
- **Ghost grid.** Re-traces the previous mask for the same pixel; display only, correct.
- **Length contraction (`cdist`, γ_Z).** Ehrenfest-type convention, labelled as such; X-PSI uses coordinate spot
  sizes and γ only in dS′ = γ dS [code].
- **Oblate surface in `beamRays`** uses the spherical R; **`buildRays` occulter** uses R(1 + o₂/2) (a mean radius):
  minor inconsistencies with the shader's exact R(θ).
- Units: all km/c = 1 conversions checked (Ω_km, J, ω, Tref, Lff, μ); no unit errors found.
